## TL;DR

Converge был не compute-bound, а последовательным: 12% CPU всего запуска при 55% wall, главный поток держал 16% CPU, втрое больше любого воркера. Проход переписан на тела вместо определений, целочисленные id с предвычисленными редкостями, параллельные сортировки вместо хеш-таблиц и shortlist до постройки находок. Lens-режим (`--kinds lenses`) получил дедупликацию по содержимому внутри Python-фронтенда с подсчётом близнецов для `use`-линзы и префильтр перед точным кластеризатором, которому 79% символов никогда не были нужны. Converge: 3.9 s → 0.8 s на `mono`, 1.25 s → 0.37 s на `mixed`; lens-запуск на `mono`: 16.2 s → 7.7 s. Все десять режимов parity побайтово идентичны 0.12.0 на обоих корпусах, включая 278 МБ нераскапченного ранкинга.

## Что было

- **Converge = склейка на одном потоке.** Индекс утверждений по `&str`, `HashSet`-дедуп 7.9M сидов, `HashMap<(usize,usize), Pair>` на 1.85M пар, строковый хеш + `ln` на каждый lookup редкости (`peak` один был 1.6% CPU всего запуска), 385k `Finding` построены и отсортированы, чтобы cap оставил сотню. Профиль по функциям говорил «ничего не доминирует», профиль по потокам показал, где время.
- **Lens-режим парсил все близнецы.** Движок в этом режиме намеренно не дедуплицирует файлы: `use`-линза считает упоминания имени по всему набору. Итог на `mono`: 28 763 парса вместо 4 796, каждый файл прочитан и распарсен дважды (body-скан и use-walk), `scope`-линза делала три канонизации на функцию и читала одну.
- **pass1 по lens-записям строил суффиксный автомат на каждую строку**, хотя собственные bound'ы difflib-fast (длина, мультимножество символов) выкидывали большинство пар до сравнения. 79% символов уходили в автоматы зря.
- Мелочи, каждая на одном потоке: `score_lens_defs` c `BTreeSet` на запись, интернинг и df в type-3 последовательно, клонирование 13M строк перед join'ом, `realpath` на каждый из 28k файлов в рендере.

## Что стало

- **Converge на телах.** 219k определений → 31k тел; всё текстовое (токены, ключи, формы, редкости, tally) строится раз на тело. Определение = `(def, body, subject-set)`.
- **Ключи и формы интернированы в лексикографическом порядке**, имена и строки по хешу; редкость = чтение массива. Порядок несущий: обход сидов идёт по порядку ключей, а суммы форм по порядку форм, оба были строковыми.
- **Сортировка и решение по парам**: сиды упакованы как `(a<<32|b, idx)`, `par_sort`, внутри пары применяется правило «дедуп + длиннейший прогон, первый при равенстве» в исходном порядке.
- **Развилки мемоизированы по id строк разрыва** (703k сигнатур → 418k развилок на `mixed`) и anti-unify идёт по уже лексированным токенам; хранится только терм, имена дырок пересчитываются для сотни выживших.
- **Shortlist до materialize**: ранжирование по thickness, оставляем всё не ниже `top`-го своего вида, строим `Finding` только для них, сортируем по полному ключу, режем.
- **Lens: близнецы считаются, а не обходятся.** `py-canon` читает все файлы, парсит один на содержимое, реплеит def'ы на копии, отдаёт `use_facts` каждый distinct-источник с кратностью. Дефолтный `Frontend::scans_across_files` даёт движку дедуплицировать остальные фронтенды и пересчитывать их corpus-relative score по реплеенному набору.
- **Префильтр перед `cluster_canonicals_chars`**: те же две точные верхние границы, что применяет сам кластеризатор, строки без партнёра не передаются вовсе. pass1 по lens-записям 4.0 s → 1.5 s.
- Параллельный `score_lens_defs`, параллельные интернинг/df в type-3 с borrowed line lists, `scope`-линза считает одну строку из трёх, module-scope переименование смотрит в два множества вместо клонирования объединения на функцию, рендер резолвит real path на директорию + `lstat` на файл.

## Что изменилось

### `crates/find-dup-defs/src/converge.rs`

Переписан целиком, публичный контракт (`pass_converge`, `SEED_CAP`, секции) тот же. Ключевые узлы:

```rust
/// One distinct body — the lines, their nesting, the vocabulary they are read in — and everything
/// the pass derives from those three alone.
struct Body<'a> {
    lines: Vec<&'a str>, line_ids: Vec<u32>, depths: Vec<u16>, vocab: Vocab,
    keys: Vec<u32>, shapes: Vec<u32>, lexed: Lexed<'a>,
    name_starts: Vec<u32>, name_ids: Vec<u32>, views: Vec<u32>,
    // derived once the corpus is counted
    named: Vec<bool>, key_rarity: Vec<f64>, anchor: Vec<Option<(f64, u32)>>,
    key_set: Vec<u32>, shape_set: Vec<u32>, shape_counts: Vec<u32>,
    first_of_shape: Vec<u16>, shape_slot: Vec<u16>,
}
```

Решение по парам после сортировки вместо `HashMap` + `HashSet`:

```rust
let mut order: Vec<(u64, u32)> = seeds.par_iter().enumerate()
    .map(|(i, sd)| ((u64::from(sd.a) << 32) | u64::from(sd.b), u32_of(i))).collect();
order.par_sort_unstable();
let starts = run_starts(&order, |x, y| x.0 == y.0);
let runs = starts.par_windows(2).filter_map(|w| { /* dedup + longest, in seed order */ }).collect();
```

Развилка как терм, без строк дырок; anti-unify по лексированным токенам с проверкой закрытости кавычек (`Lexed.closed`), иначе точный fallback на текст. Shortlist:

```rust
let candidates = shortlist(candidates, top); // всё не ниже top-го thickness своего вида
// ... Finding строятся только для них, затем par_sort по (thickness, name, members) и cap
```

Ловушки точности, которые пришлось сохранить и которые ловил parity: `max_by` возвращает ПОСЛЕДНИЙ максимум (anchor), имена читаются per (текст ключа, vocab) — s-expr-ключи имён не содержат, tie-break LGG несимметричен (печать развилки в ориентации и vocab сида), склейка разрыва `"; "` лексируется как конкатенация только если строки закрыли кавычки.

### `crates/find-dup-defs/src/lib.rs`

- `cluster_distinct`: `candidates()` применяет length bound и multiset bound (те же формулы и floats, что в difflib-fast) и отдаёт кластеризатору только строки с партнёром, индексы маппятся обратно.
- `collect_defs`: решение о дедупе per-frontend через `scans_across_files`; после реплея на близнецов в lens-режиме `score_lens_defs` по полному набору; реплей клонов параллельный.
- `pass_type3`: line lists и имена borrowed; `pass_cross_name`: bucket'ы по `FxHashMap`, квалифицирующие сортируются по канону (тот же порядок, что давал `BTreeMap`); `large_name_groups` на `FxHashMap`.

### `crates/find-dup-defs/src/type3.rs`

`type3_clusters(&[&[String]], &[&str], ..)`: интернинг строк через `par_sort` + `dedup`, df через `fold`/`reduce` по потокам.

### `crates/find-dup-defs/src/main.rs`

`FDD_BENCH=converge:N`; `phase_bench` применяет фильтр `--kinds` и сортировку как `cluster()`. Рендер: `short_paths` резолвит real path на директорию и `lstat`'ит файл; символическая ссылка или сбой идут прежним путём через `canonicalize`.

### `crates/py-canon/src/frontend.rs`, `uses.rs`, `canon.rs`, `defs.rs`

- `Python::scan` в lens-режиме: чтение всех файлов, дешёвый digest + побайтовое сравнение, парс distinct, параллельный реплей, `use_facts(&[(&str, usize)], ..)` с кратностью.
- `build_profiles` несёт `(Site, usize)`: повторный сайт сортируется рядом с собой, новый слот не нумерует, факт добавляется столько раз, сколько копий.
- `scope_canonical` вместо `analyze_in_scope`: одна отрисовка вместо трёх; `Dump::rename_id` смотрит в `locals` и `scope` по очереди вместо объединения множеств на каждую функцию.

### `crates/dup-defs-core/src/types.rs`, `lens.rs`, `Cargo.toml`

Дефолтный `Frontend::scans_across_files(&self, opts) -> bool { false }`; `score_lens_defs` через `rayon` fold/reduce (df) и `par_iter` (score), суммирование в том же отсортированном порядке фактов. Зависимость `rayon`.
