# converge: 4.5x faster, and `--json` now says which pass found a thing

Converge was the one pass still running single-threaded while the rest of the tool sat at 563% CPU.
On a 25k-definition tree it took **11.0s of the 11.7s total**. Now it takes 1.2s.

One squashed commit: 5 files, +339 / −192. Human output byte-identical; the JSON document gains one
field.

---

## Where the time actually was

Phase timings before, on a real corpus (25 128 definitions across four trees):

```
views              0.22s
corpus             0.12s
statement seeding  2.77s   → 169 814 pairs
subject seeding    1.07s   → 292 955 pairs
weighing           6.81s   → 124 585 findings, of which 800 are printed
```

Two of my guesses were wrong and both died on a measurement, which is the only reason the right
four changes got made:

- *"the expensive part is building 124k findings"* — deferring the rendering and the source clone
  won **0.25s of 6.8**. Real, but not the problem.
- *"`large.contains(node)` is a linear scan"* — `subjects` is a `HashSet`; the edge build was
  **22ms of 735**. The scan was my invention.

## The four changes

**The hasher.** Converge is almost entirely hash lookups over interned strings, and it used SipHash.
FxHash — already a dependency, for the Type-3 pass's hot maps — is the right tool for keys that are
not adversarial input. Weighing **6.6s → 4.1s** on that alone.

**Explaining a finding only if it survives the cap.** The pass reports a *ranking* capped at a few
hundred, but built all hundred and twenty thousand findings whole first — rendering the agreed run,
the fork, and cloning each definition's entire source — then dropped 99.7% of them. The cap moved
inside the weighing, ahead of that work. Sorting is unaffected: neither the notes nor the snippet is
one of its keys.

**Three parallel phases where there was one loop.** Each seeding pass split along what can actually
be computed independently:

| | |
|---|---|
| per-pair, no shared state | growing a block, anti-unifying a fork |
| shared table, order load-bearing | "this run was already seeded by another statement"; "a pair keeps its **longest** run"; "this family already appeared at a more specific subject" |

So: compute in parallel, decide sequentially, walking the same pre-sorted key list the
single-threaded loop walked.

```
statement seeding  2.77s → 0.42s
subject seeding    1.07s → 0.12s
family cliques     0.73s → 0.22s
```

**The cluster key off the sequential path.** It builds a string per pair, and there are hundreds of
thousands of pairs; it now happens in the parallel phase that already visits each one.

## Determinism

Not a side effect here — it is what makes a ranked report worth reading, so it is enforced rather
than hoped for. The weighing walks pairs **sorted by key**, not the hash table, and `collect` on an
indexed parallel iterator keeps positions. The result depends on neither the core count nor which
worker finished first.

## Result

```
converge, whole corpus     8.32s → 1.84s   4.5x
converge, one tree         1.82s → 0.44s   4.1x
converge uncapped          2.74s → 1.38s   2.0x
default report             0.49s → 0.48s   unchanged
```

Uncapped matters more than the others: that is the whole ranking rather than its head, so a single
last-bit drift in a float sum would reorder the tail and show up as a diff.

## Two defects the integration surfaced

**`--json` did not say which pass found a thing.** The human report separates passes by section
heading; the machine one merged them into a list where the advisory converge ranking carried the
same `dup-function` as a gating pass. A consumer had to guess from side effects — an absent
`min_sim` together with a present `facets` — which is to say, build its own model of what the tool
declined to state about itself. `Finding` already knew its `pass`; it is now serialized:

```json
{ "kind": "FUNCTION", "name": "a / b", "severity": "INFO", "pass": "converge", … }
```

Purely additive — **145 lines added to the reference document, none removed, every one of them the
new field**.

**`--kinds lenses` still advertised itself as "(Python only)"** in `--help`, three languages after
that stopped being true.

## Verified rather than assumed

Compared against a binary built from `main`, over two trees:

- **human output byte-identical** in six modes — converge, the default report, lenses, patternology,
  `--calibrate`, and converge on Rust;
- **JSON differs by exactly the new field**: 0 lines removed, 145 added, all `"pass"`;
- earlier in the branch, before the JSON change, all seven modes including `--json` and
  `--converge-top 0` were byte-identical after each of the four performance changes;
- `cargo test --release` **137 tests** and `cargo clippy --release --all-targets` green;
- the self-gate (`find-dup-defs crates -D @find-dup-defs.directives`) still reports 0 ERROR.

## Versions

`find-dup-defs` **0.9.0 → 0.10.0**. Minor rather than patch because the JSON document gained a
field: additive for a reader of known keys, but no longer byte-identical, and 0.9.0 shipped
promising it would be. `dup-defs-core` and the three frontend crates are untouched and are not
republished.
