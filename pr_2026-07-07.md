## TL;DR

Раздаём `find-dup-defs` на PyPI по «ruff-модели»: скомпилированный Rust-бинарь
едет внутри платформенных wheel'ов, а не собирается на машине пользователя.
Backend — `maturin` с `bindings = "bin"`: wheel оборачивает бинарь как
console-script, так что `pip install find-dup-defs` / `uvx find-dup-defs` кладут
`find-dup-defs` в PATH. Отдельный workflow собирает полную матрицу колёс + sdist
в один артефакт; публикация остаётся ручной через `uv publish`.

## Что было

Единственный канал доставки — `cargo install find-dup-defs` или ручное скачивание
бинаря из GitHub Releases. Для Python-аудитории (а инструмент таргетит в т.ч.
Python-кодовые базы) не было ни `pip install`, ни `uvx` — то есть нельзя было
подтянуть его как dev-зависимость или дёрнуть разово без Rust-тулчейна.

## Что стало

- **CLI-only Python-пакет** — никакого importable-модуля: `bindings = "bin"`
  просто регистрирует бинарь как entry-point. `uvx find-dup-defs ./src` работает.
- **Версия — из одного источника**: `dynamic = ["version"]` тянет её из
  `crates/find-dup-defs/Cargo.toml` (сейчас `0.7.6`), дублирования нет.
- **Полная матрица колёс под все платформы** (7 wheel + sdist):
  - Linux **x86_64** и **aarch64** — и manylinux (glibc), и musllinux (musl);
  - macOS **arm64** и **x86_64** (Intel кросс-компилится на arm-раннере, как в `CI.yml`);
  - Windows **x86_64** (MSVC).
- **sdist самодостаточен**: `maturin` кладёт в него весь workspace (все
  sibling-крейты + `Cargo.lock`), поэтому на неохваченной платформе `pip install`
  соберётся из исходников при наличии Rust — без обращения к crates.io за
  path-зависимостями.
- **Публикация off-CI**: workflow только собирает и сливает всё в один артефакт
  `find-dup-defs-dist`; апает `uv publish` вручную.

## Что изменилось

### `pyproject.toml`

Новый файл в корне. `build-system` → `maturin>=1.7,<2`. `[tool.maturin]`
указывает на манифест бинарного крейта в workspace и включает bin-bindings:

```toml
[tool.maturin]
manifest-path = "crates/find-dup-defs/Cargo.toml"
bindings = "bin"
```

Метадата: SPDX `license = "MIT"` + `license-files`, `requires-python = ">=3.8"`
(бинарному wheel Python не нужен — годится любой, что умеет ставить wheel),
classifiers, keywords и URL'ы репозитория.

### `.github/workflows/wheels.yml`

Новый workflow на `PyO3/maturin-action`. Триггеры — тег `v*` (та же схема, что у
релиза бинарей в `CI.yml`) и `workflow_dispatch`. Три джобы:

- `wheels` — matrix из 7 таргетов; aarch64-Linux собирается **нативно** на
  `ubuntu-24.04-arm` (без QEMU), Intel-macOS кросс-компилится на arm-раннере;
- `sdist` — `maturin sdist`;
- `merge` — `actions/upload-artifact/merge` складывает все per-target артефакты в
  один `find-dup-defs-dist` с плоским `dist/`, готовым под `uv publish dist/*`.

### `.gitignore`

Добавлен `dist/` — выхлоп сборки wheel/sdist.

## Проверка

Всё прогнано **локально** на этой машине (macOS arm64), не на словах:

| Что проверяем | Результат |
|---|---|
| `maturin build` | `find_dup_defs-0.7.6-py3-none-macosx_11_0_arm64.whl`, бинарь внутри в `.data/scripts/` |
| Установка + запуск | ставится в venv, `find-dup-defs --version` → `find-dup-defs 0.7.6`, нативный Mach-O arm64 |
| Версия | `0.7.6` подхватилась из `Cargo.toml` через `dynamic` |
| sdist из исходников | `uv pip install --no-binary` собрал из sdist в изоляции → рабочий бинарь |
| `twine check dist/*` | **PASSED** для wheel и sdist (`License-Expression: MIT`, `Requires-Python`, classifiers) |
| YAML | оба workflow парсятся |

Матрицу под Linux/Windows соберёт CI (для них нужны manylinux-контейнеры,
локально с macOS не собрать). Публикация после мержа: `gh run download <run-id>
-n find-dup-defs-dist -D dist && uv publish dist/*`.
