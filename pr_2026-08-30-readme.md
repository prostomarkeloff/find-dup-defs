# A README you can navigate — and three claims in it that were wrong

The README had reached 696 lines of flat prose with no table of contents, no way to jump, and no
sample of the report the tool actually prints. Three deep-dive essays — patternology, lenses,
converge, 282 lines between them — sat *between* the core story and the two sections that make the
case for the tool at all (the benchmarks and the results on 38 real repos).

One commit: 1 file, +439 / −283. No code touched.

---

## The shape problem

The content was not the issue; the ordering and the density were. A reader arriving cold met the
hook, then 280 lines of mechanism, and only then found out the thing is 2–5× faster than PMD CPD.

| lines visible on load | 696 | **584** |
| lines folded into `<details>` | 0 | 268 |
| internal navigation links | 0 | **22** |

Restructured rather than trimmed — nothing was dropped, and the mechanism sections keep every

## Three claims that were wrong

Found while grounding the prose against the source, not by reading the prose.

**Lenses were documented as Python-only.** The Limitations ledger said "Lenses are Python-only",
which contradicted the Lenses section forty lines above it saying "Python, Rust and TypeScript".
The section was right: `lenses.rs` exists in all three frontends and has since the machinery moved
into `dup-defs-core`. Only the `use` lens is genuinely Python-only — it needs the tree-wide mention
index that `py-canon/src/uses.rs` builds, and no other frontend has one. The ledger now says that
instead.

**The speed claim contradicted its own table.** It read "2–12×" in the opening and "3–12×" in the
Performance section, and neither matched the numbers underneath:

| | range in the table |
|---|---|
| vs PMD CPD | 2.1× – 4.9× |
| vs jscpd | 8.4× – 18.2× |

Collapsing two different tools into one range understated jscpd and overstated PMD. It now reads
**2–5× against PMD CPD and 8–18× against jscpd** — both accurate, and the honest version is the
better headline.

**`settings:converge-cap` was undocumented.** Shipped in 0.12.0, absent from the README. It is now
in a settings table alongside `max-name-group`, `pattern-min-thickness` and `gpu`, and in the
converge section with the finding that matters: lowering it is not a free speedup — cap 20 costs
nothing on a duplication-heavy monorepo but drops 70% of the pass's findings on ordinary code.
`--repo-root` was missing from the flag list too.

## Verified

- **22 internal anchor links, 0 broken** — checked by generating GitHub's anchor slugs from the
  headings and diffing against every `](#…)` target.
- **Balanced markup**: 40 code fences, 10 `<details>` / 10 `</details>`, 2 `<div>` / 2 `</div>`.
- **The console samples are real runs**, captured from `target/release/find-dup-defs` on this
  workspace; the summary lines (`21 ERROR, 24 WARNING`) are the binary's own.
- **The self-gating claim still holds**: `find-dup-defs crates -D @find-dup-defs.directives` exits
  0 with `0 ERROR, 37 WARNING`.
- **No local-only paths leaked.** `Makefile`, `scripts/` and `perf-local/` are in
  `.git/info/exclude`, so a reference to them would be dead after a clone; the README has none. The
  benchmark methods are described, the harnesses are not cited.

Benchmark numbers were left exactly as measured — nothing in this branch re-ran them.

## Noted, not fixed

but `patternology.rs` has carried `PyDialect`, `RustDialect` and `TsDialect` for a while. The README
was right and `--help` is wrong. Left alone because this branch touches no code — worth a one-line
follow-up.
